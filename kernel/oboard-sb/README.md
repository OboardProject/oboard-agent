# oboard-sb

`oboard-sb` is OBoard's slim sing-box kernel. It is built as a separate Go module so the Controller and Agent stay independent from the proxy core.

It follows the minimal registry approach used by `ashvvvvv/mini-sb-agent`, but only for the sing-box kernel. No Agent, panel sync, Xboard client, or SSH/manual configuration flow is copied.

## Supported protocol surface

- VLESS, including TLS/Reality config generated by OBoard.
- Hysteria2 / HY2.
- AnyTLS.
- Shadowsocks / SS.
- WireGuard endpoint for Controller-managed WARP profiles.

## Build

From repository root:

```bash
./scripts/build-oboard-sb.sh
```

Cross build example:

```bash
GOOS=linux GOARCH=amd64 ./scripts/build-oboard-sb.sh
GOOS=linux GOARCH=arm64 ./scripts/build-oboard-sb.sh
```

## Run / check

```bash
kernel/oboard-sb/oboard-sb -check -config config.json
kernel/oboard-sb/oboard-sb -config config.json -api unix:/tmp/oboard-sb.sock
```

Runtime defaults are selected from the detected host:

- Effective memory below 512 MiB (or unknown) uses the small profile. Multi-GiB containers are no longer forced small.
- Hosts with at least 512 MiB effective memory use the large profile, including Docker/LXC/Incus when the cgroup memory limit is large enough.
- A local `large` profile request is still downgraded on known low-memory hosts.
- Soft limit **fills residual memory** after Agent + socket + OS reserves (use the box; do not idle half of it). Inspired by mini-sb-agent's fixed `GOMEMLIMIT=40MiB` on 128–256 NAT hosts, but scaled by effective memory.
- Small profile is adaptive:
  - ≤96 MiB micro: 1 P, `GOGC=50`, residual soft limit (floor 20 MiB)
  - ≤128 MiB micro: 1 P, `GOGC=70`, residual ≈64 MiB on a 128 MiB box
  - ≤192/256 MiB compact: 1 P, `GOGC=70/80`, residual soft limit
  - <512 MiB small: up to 2 Ps, `GOGC=90`, residual soft limit
- Large profile budgets by capacity class:
  - 512 MiB–1 GiB standard: ≤2 Ps, `GOGC=100`, residual soft limit
  - 1–2 GiB performance: multi-core (cgroup-aware), `GOGC=100–120`
  - ≥4 GiB high: multi-core, `GOGC=150`, residual soft limit (ceiling 4 GiB)
- `GOMAXPROCS` prefers cgroup CPU quota when tighter than `runtime.NumCPU`.
- Socket reserve is the main anti-OOM term: multi-conn NAT OOM is usually TCP pages, not the Go heap. Adaptive peak/balanced/safe caps keep socket pages bounded while Go uses the rest.
- `-gomaxprocs` and `-memory-limit-bytes` remain explicit local operator overrides; the Controller does not change them remotely.
- Generated log level defaults to `warn` if not specified.
- HY2 tuning flags are available for low-memory/NAT deployments.
- User traffic wrappers preserve sing-box `ExtendedConn`, use independent upload/download token buckets, and bound limited TCP reads/writes to 64 KiB without maintaining per-connection queues. UDP/QUIC limiting is non-blocking.
- Unrestricted billable TCP users expose the official sing `ReadCounter`/`WriteCounter` interfaces. Traffic remains accountable while sing-box can unwrap the accounting layer and retain its optimized direct/extended copy path. Speed-limited users remain wrapped by the token bucket.
- Cgroup-limited nodes under 1 GiB return idle Go pages under sustained memory pressure without rejecting or closing connections.
- TCP socket auto-tuning uses peak / balanced / safe caps (128 MiB peak matches mini-sb-agent's ~1.6 MiB max). Watermarks count billable tracked TCP connections and stay high enough for a single browser user with parallel streams. Performance restores only after a stable low-load window. Governor remains active through 512 MiB–1 GiB hosts and is disabled at ≥1 GiB.
